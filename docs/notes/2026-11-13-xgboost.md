# XGBoost
Created: 2026-11-13
Scope: How gradient-boosted trees (step 3 of `2026-11-10-model-comparison-plan.md`) are encoded, tuned and reported, laid out by the notebook's sections.

## Setup

- **Notebook:** `analysis/xgboost_model.py`, paired with an `.ipynb`. Results in `results/xgboost/`. The file isn't named `xgboost.py`, since that would shadow the package on import.
- **Dependency:** `xgboost` 3.4.1, added with `uv add`. On macOS it also needs the OpenMP library, which uv can't install and the XGBoost wheel doesn't bundle, so run `brew install libomp` once per machine. CLAUDE.md's new-machine steps say so. Without it, `import xgboost` fails. Pointing `DYLD_LIBRARY_PATH` at scikit-learn's bundled copy also works, but it has to be set in every shell and kernel, so it was dropped.
- **Model:** `XGBClassifier` with `objective="binary:logistic"` and `tree_method="hist"`.
- **Encoding:** full one-hot from `common.make_encoder()`, as for every non-baseline model. XGBoost's own categorical splits were considered and dropped. They can group hundreds of diagnosis levels freely, which overfits easily, and rare levels would need handling outside the shared encoder. One-hot gives every model the same inputs.
- **No class reweighting:** `scale_pos_weight=1`. XGBoost's tuning notes say not to rebalance when calibrated probabilities are needed.
- **Folds:** each fold is encoded once with `common.encode_folds`, as in the tree notebook.

## Tuning

### Fixed settings

| Setting | Value | Why |
| :--- | :--- | :--- |
| `learning_rate` | 0.1 | Trades off against the number of trees, which is tuned. The value used in the XGBoost paper and common guides |
| `gamma`, `reg_alpha`, `reg_lambda` | 0, 0, 1 (defaults) | Probst, Boulesteix & Bischl (2019) found tuning them worth about 0.003 AUC |
| `n_estimators` | 2,000, a cap | The number actually used is chosen by CV, below |

### Grid

| Setting | Values | Count |
| :--- | :--- | :--- |
| `max_depth` | 4, 6, 8 | 3 |
| `min_child_weight` | 1, 10 | 2 |
| `subsample` = `colsample_bytree`, tied | 0.8, 1.0 | 2 |

12 settings × 5 folds = 60 fits.

- **`max_depth`:** sources disagree. Ryan Tibshirani's CMU lecture notes, summarizing ESL §10.11, favour shallow trees with 2–8 leaves. XGBoost's default is 6, and Probst found deeper trees best. The range spans them.
- **`min_child_weight`:** the minimum data in a leaf, like `min_samples_leaf` for the tree. Probst ranks it among the settings most worth tuning. 10 smooths the leaves, which suits about 288,000 stays per fold.
- **Subsampling:** Probst's best values are 0.75–0.85, and 1.0 is XGBoost's default of none. Tying rows and columns keeps the grid small.

### Number of trees

The number of trees is tuned like any other setting. One number is chosen for all folds.

- **Each fit:** grows all 2,000 trees and records the validation fold's AUC and Brier after every tree. A model with k trees is the first k trees of that fit, so every count from 1 to 2,000 is scored without extra fits.
- **Brier per tree:** XGBoost's `rmse` metric on `binary:logistic` is computed on the risks, not the log-odds, so Brier = rmse². Checked on simulated data with XGBoost 3.4.1: across all 200 tree counts, rmse² matched scikit-learn's `brier_score_loss` to within 2e-8, a float32 rounding gap far below the differences between settings. XGBoost's per-tree AUC matched `roc_auc_score` exactly. With no sample weights, nothing else changes either metric.
- **No per-fold early stopping:** stopping each fold where its own validation fold peaks would let that fold both choose and grade the model, so the CV score would come out optimistic. Choosing one count from the averaged curves is the same CV selection as α for the tree and C for the lasso, so it needs no extra data.
- **OOB:** not used. XGBoost doesn't bootstrap and has no OOB option. The trees a row was left out of still build on earlier trees that saw it. scikit-learn's user guide calls boosting OOB estimates "very pessimistic" and recommends CV. Lecture 13 limits OOB to bootstrapped methods and says every model should be compared on the same K-fold CV.

### Chosen model

- **Choice:** the setting and tree count with the best mean CV AUC. No one-standard-error rule, as for the lasso and the tree.
- **Edge check:** if the best count is at the 2,000 cap, raise the cap. If the best `max_depth` or `min_child_weight` is at an edge of its range, extend that range by one step (depth 10 or 2, `min_child_weight` 30).
- **Fold scores:** the chosen setting is refit on the 5 folds at the chosen count, for `cv_scores.csv` and the out-of-fold predictions. That's 5 extra fits, and it avoids keeping all 60 fitted models.
- **Per-fold details:** the number of trees, and each fold's own best count, to show how stable the choice is. Passed to `common.fold_scores`.
- **How it runs:** as in the tree notebook, with the fits in parallel through joblib. XGBoost's threads per fit are set so the total stays at 8 cores. Time one fit before running the grid.

### Tuning curve

Mean CV AUC against the number of trees, one line per setting, with a mark at each line's best count. Panels by `max_depth` if 12 lines are too many to read. `tuning.csv` has CV AUC and Brier for each setting at its best count. The best-setting table uses `common.show_scores(highlight=True)`.

## Final model

- **Refit:** on all of train with the chosen setting and tree count. The count is kept as is, though the final model sees 25% more data than each fold. Sources differ on scaling it up, and leaving it unchanged is simplest.
- **Recalibration set:** never used to choose the count.
- **Feature importance:** total gain summed over each feature's one-hot columns, one row per original feature. A table and a bar chart, saved as `feature_importance.png`, with a short commentary. It has the same two limits as the tree's importance: it favours features with many levels, and it's measured on training data. No readable tree, since one tree out of hundreds says little.

## Recalibration

The same steps as the lasso and the tree. The final model predicts the recalibration set, then `common.fit_recalibrators` fits Platt and isotonic. The test set isn't touched. The scoping note expected boosted trees to be overconfident and to gain the most from recalibration, so the before-and-after calibration curves are the main thing to check.

## Findings

CV AUC and Brier against the baseline, the lasso and the tree, the chosen setting, and what recalibration changed.
